# comment-gen

수정·추가한 코드에 변경 이력 주석을 다는 기능. 주석 형식은 사용자가 정한다.

## 사용자 안내

설명: 에이전트가 코드를 고칠 때 바뀐 자리마다 날짜·작성자·작업 내용을 적은 변경 이력 주석을 기존 코드와 같은 형식으로 달아 줍니다. 주석을 넣기 전에 넣을 위치와 문구를 먼저 보여 주고, `진행`이라고 답해야 실제로 넣습니다.

물어볼 것

1. `[못 찾을 때]` (기존 코드에 같은 형태의 이력 주석이 반복되지 않을 때만) 코드를 고칠 때 변경 이력 주석을 자동으로 달까요?
   - 정하는 것: 이 기능을 켤지. 반복되는 이력 주석이 있으면 묻지 않고 켠다
   - 선택지: 단다 / 달지 않는다
   - 추천: 달지 않는다
   - 모름/나중에: 달지 않는다(설치하지 않음). 나중에 다시 설치할 수 있다
2. `[못 찾을 때]` (VCS 사용자 이름이 비었고 기존 이력 주석에서도 확실히 찾지 못할 때만) 주석에 들어갈 작성자 이름은 무엇인가요?
   - 정하는 것: `[person] author`
   - 선택지: 이름 알려 줌
   - 모름/나중에: 비워 둠. 처음 주석을 넣을 때 comment-gen 스킬이 묻고 적는다

묻지 않고 정하는 것

- 주석 형식(`[comment-gen] format`, `file_types`): 기존 이력 주석에서 뽑은 형식
- 위치를 정하는 시점(`[comment-gen] timing`): `"after"`(작업이 끝난 뒤 한 번에)
- 작성자(`[person] author`): VCS 사용자 이름. 기존 이력 주석에 다른 표기(한글 이름 등)가 반복되면 그 표기

## 감지 신호

- 기존 코드에 날짜·작성자 형태의 이력 주석이 반복되는지(형태 `YYYY.MM.DD 이름: 내용`)
- 없으면 사용자에게 쓸지 묻는다(사용자 안내 1)

## 원칙

- 작성자·티켓·접두를 지어내지 않는다
- 주석 금지 구간(`[comment-gen] exclude`)에는 넣지 않는다
- 주석만 추가한다. 로직·포맷을 같이 바꾸지 않는다
- 주변 기존 이력 주석의 위치·들여쓰기·정렬을 따른다
- 적용 전에 배치안을 보여 주고 `진행`을 받는다

## 규칙 작성 항목 (set-up-harness가 묻거나 기존 주석에서 뽑음)

| 항목 | 키 |
|---|---|
| 주석 형식 | `[comment-gen] format` (형식 `YYYY.MM.DD {author}: {접두} {작업내용}({티켓})`) |
| 리포트 등 별도 형식 | `[comment-gen] report_format` (선택) |
| 대상 파일과 주석 문법 | `[comment-gen] file_types` (형식 `{".java" = "//", ".xml" = "<!-- -->"}`) |
| 주석 금지 구간 | `[comment-gen] exclude`: `"<파일 glob>: <금지 구간>"` 문자열 목록. nexacro 기능을 함께 켜면 `"*.xfdl: <Script> CDATA 밖 전체(Layout·Objects·Dataset XML)"`를 넣고 `file_types`에 `".xfdl" = "//"`를 둔다. `.xfdl` 주석은 Script CDATA 안에만 단다 |
| 적용 시점 | `[comment-gen] timing` = `"plan"`(계획 단계) / `"after"`(구현 후, 기본). 계획·작업 스킬이 이 값을 보고 comment-gen을 부를 때를 정한다 |
| 작성자 | `[person] author` |
