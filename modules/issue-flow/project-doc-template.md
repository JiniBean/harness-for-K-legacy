# 프로젝트 issue-flow 문서 템플릿

set-up-harness가 프로젝트의 `.agents/docs/issue-flow.md`에 아래 절을 쓴다. 값은 사용자에게 묻거나 이슈 관리 도구 MCP로 조회해서 채운다. 조회로 확인하지 못한 값은 `미확인`으로 두고 지어내지 않는다.

값 표기 `{…}`·`[tracker.fields] …`는 `.agents/harness.toml`의 같은 키를 Read해서 쓴다.

필드 ID·사이트는 이 문서가 아니라 `harness.toml` `[tracker]`·`[tracker.fields]`에 둔다. 이 문서에는 이름으로만 가리킨다.

## 절 목록

| 절 | 내용 | 채우는 방법 |
|----|------|-------------|
| 도구 | Jira / GitHub Issues / 없음 | 사용자 답 + MCP 연결 여부 |
| 키 형식 | 키 접두(예: `ABC`), 순수숫자에 붙일 기본 접두 | 커밋 메시지·브랜치 이름, 사용자 확인. 같은 접두로 스킬 본문의 `<KEY>`를 바꾼다(MODULE.md 「설치 변형」) |
| 내 담당 조회 | JQL(또는 GitHub 검색 조건) 1개 이상. 착수 후보만 보는 JQL이 따로 있으면 함께 | 사용자 답 → `searchJiraIssuesUsingJql` 1회로 건수 확인 |
| 상태 이름 | 워크플로 순 상태 이름 목록(`--status-order`에 그대로 넣음), 가능하면 상태 ID | 조회 결과의 `status.name` |
| 상태 전환 | 착수 전 상태, transition 이름, 착수 후 상태. 전환하지 않으면 `없음` | 설치 때 `미정`. 처음 착수 때 issue-flow 스킬이 착수 전 티켓 1건에 `getTransitionsForJiraIssue`로 조회해 사용자가 고른 값 |
| 착수 필드 | 착수 시 기입할 필드 이름(`[tracker.fields]` 키)과 묻는 순서, 타입, 재질문 조건(값이 있어도 다시 묻는 경우). 적지 않으면 `없음` | 설치 때 `미정`. 처음 착수 때 issue-flow 스킬이 묻고 채움 |
| 필드 옵션 | select 필드마다 표시 순서 · 표시명 · option id 표 | 착수 필드를 정할 때 `getJiraIssueTypeMetaWithFields` 또는 기존 티켓 값 |
| 날짜 보기 | 날짜 칸 후보를 만드는 방법(예: 진행 중 상태 티켓의 고유 예정일, 이번 달~다다음 달). 없으면 `MMDD`만 | 사용자 답 |
| 정렬 필드 | §2 목록 정렬에 쓸 `[tracker.fields]` 이름(`--sort-field`). 없으면 기한만 | 사용자 답 |
| 대상 확정 | 티켓 → 화면·파일을 좁히는 프로젝트 절차(메뉴 문서, 라우트 표 등). 없으면 `없음` | 프로젝트 구조 확인 |
| 계획 추가 항목 | 계획 착수분석에 더할 표(고객사·메뉴 대응 등). 없으면 `없음` | 사용자 답 |
| 검증 후 단계 | `/verify` 통과 뒤 제안할 단계(빌드·배포 스킬 이름, 넘길 값, 승인 문구). 없으면 `없음` | 프로젝트 스킬 목록 |
| 쓰지 않는 필드 | 이 스킬이 절대 기입하지 않을 필드(요청 본문, 다른 팀 필드 등) | 사용자 답 |

## 작성 규칙

- 회사·팀 고유 값은 이 문서에만 둔다. 공용 스킬 문서(`skills/issue-flow/`)에 옮겨 적지 않는다
- 토큰·비밀번호는 쓰지 않는다. 토큰 파일 경로는 `harness.toml` `[paths] jira_token_file`
- option id·transition 이름은 조회 결과를 그대로 옮긴다
- `미정`은 아직 묻지 않았다는 뜻이다(issue-flow 스킬이 처음 착수 때 묻는다). `없음`은 사용자가 쓰지 않기로 정했다는 뜻이라 다시 묻지 않는다
