# 계획 파일 형식 (issue-flow)

값 표기 `{…}`·`[tracker.fields] …`는 `.agents/harness.toml`의 같은 키를 Read해서 쓴다.

`{티켓 키}*.plan.md` 본문 형식. Cursor `CreatePlan`(`~/.cursor/plans`)·Claude Code Write(`.agents/plans`) 공통. 위치·이름·갱신 규칙은 [workflow.md 계획 산출](workflow.md#계획-산출).

## 뼈대

````markdown
---
name: {티켓 키} {짧은 제목}
overview: {무엇이 문제고 어디를 어떻게 고치는지 2~3문장}
todos:
  - id: {kebab-id}
    content: {파일·위치·변경 한 줄}
    status: pending
isProject: false
---
````

## 규칙

- 착수분석 표는 기본 정보(항목 | 값)와 판단 근거(확인 | 결과 | 근거) 두 개가 기본이다. 프로젝트에 필요한 표(고객사·메뉴 대응 등)는 프로젝트 issue-flow 문서 §계획 추가 항목을 따른다
- 결론은 결과 열만 읽어도 보이게 쓴다. 첨부 경로처럼 긴 값은 표 아래 한 줄
- 다이어그램은 `text` 코드 블록 ASCII만. 호출 경로·분기는 `└─>`, `├─`, `└─` 트리
- 현재(as is)는 설명 → 트리 → 불릿 순서. 변경(to be)은 불릿 3줄 안팎
- `## 구현 상세` 첫 줄은 반드시 `수정 파일:`. 다음 줄 `손대지 않음:`, `파급:`
- 번호 섹션(`## 1.`~) 하나는 한 파일의 한 위치(함수·컴포넌트·쿼리)만 다룬다. 제목 형식 `{영역} — {무엇을} ({위치})`
- 번호 섹션 순서: 설명 1~2줄 → 코드 블록 → 주의 불릿. comment-gen 기능을 켰으면 이력 주석을 들어갈 자리에 넣는다
- 코드 블록의 설명용 표시(`// 250 → 265` 등)는 소스에 넣지 않는다고 그 섹션 불릿에 적는다
- 줄 번호는 `L123` 형식. 파일 링크는 저장소 기준 상대 경로
- 번호 섹션 사이는 `---`
- 서브에이전트 결과는 판단 근거 표와 현재(as is)에 녹여 쓴다. 원문을 붙이지 않는다
- 문장 안 볼드 금지. 표 헤더·제목만 허용
