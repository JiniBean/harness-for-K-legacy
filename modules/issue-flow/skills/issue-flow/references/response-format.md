# 티켓 확인 보고 형식 (issue-flow)

값 표기 `{…}`·`[tracker.fields] …`는 `.agents/harness.toml`의 같은 키를 Read해서 쓴다.

고정 섹션 제목·표 헤더·안내 문구. 값·건수는 workflow 조회 결과로 채운다. 상태 이름·필드 표시명은 프로젝트 issue-flow 문서 값을 그대로 쓴다.

---

## §1 조회 요약 (Jira·GitHub)

```markdown
## 티켓 확인 — {YYYY-MM-DD HH:mm}

### 내 담당 티켓 요약
| 상태 | 건수 |
|------|------|
| {상태 이름} | {n} |
| … | … |
| 합계 | {total} |
```

- 상태명은 도구의 `status.name` 그대로
- 건수 내림차순으로 바꾸지 않는다
- (Jira) 행 순서는 `aggregate_assigned.py` 출력 순서(`--status-order`)
- (GitHub) 행 순서는 프로젝트 문서 §상태 이름 순서

---

## §2 착수 후보 목록 (Jira·GitHub)

```markdown
### {착수 상태} ({n}건) — 작업 시작 후보

| # | 키 | 요약 | 보고자 | {정렬 필드 표시명} | 기한 |
|---|-----|------|--------|------------|------|
| 1 | <KEY>-123 | {요약} | {보고자} | 09-28 | 09-18 |

→ 작업을 시작할 티켓 키(`<KEY>-{n}` 또는 숫자)를 채팅에 입력해 주세요.
```

- 필드 미입력: `*(미입력)*`
- 날짜: `MM-DD` (연도 생략)
- 요약: 프로젝트 문서에 표시용 접두 제거 규칙이 있으면 그 규칙만 적용. 도구 원문은 고치지 않는다
- 이 마크다운을 출력하면 턴 종료
- 후보 0건:

```markdown
### {착수 상태} (0건)

현재 작업 시작 후보 티켓이 없습니다.
```

---

## §4 착수 필드 안내 (Jira·GitHub)

채팅에 옵션 ID를 쓰지 않는다. 현재 값 한 줄. 값이 있는 칸은 목록을 내지 않는다(재질문 조건에 걸린 칸은 예외).

```markdown
## 작업 시작 확인 — {티켓 키}

현재: {필드1} {value} / {필드2} {value} / {필드3} {value}

### {물을 필드 표시명}
1. {옵션 표시명}
2. {옵션 표시명}

→ {물을 필드}만 답해 주세요. 예: `1`. 유지하려면 `-`
```

날짜 칸:

```markdown
### {날짜 필드 표시명}
이번 달
1. {YYYY-MM-DD}
다음 달
2. {YYYY-MM-DD}
다다음 달
(없음)

보기 없으면 MMDD (예 `1029`).
```

- 재질문 칸이면 목록 위에 이유 한 줄(프로젝트 문서의 재질문 조건 문구)
- 여러 칸을 물으면 칸마다 섹션을 붙이고, 안내 예시는 칸 순서대로 토큰을 나열(`2 1 1029`)
- 날짜 번호는 세 달을 이어서 1부터. 해당 월이 없으면 `(없음)`

## §5 전환 사전확인 (Jira·GitHub)

물을 칸 0일 때.

```markdown
### 상태 전환 (승인 대기)

| 항목 | 내용 |
|------|------|
| 티켓 | {티켓 키} |
| 요약 | {summary} |
| 전환 | {착수 전 상태} → {착수 후 상태} |

현재 값을 유지하고 전환만 하려면 「진행」. 칸을 바꾸려면 칸 개수만큼 토큰.
```

- 이 섹션을 출력하면 턴 종료

---

## §실행결과 (Jira·GitHub)

### 완료

```markdown
## 실행 결과 — {티켓 키}

- 필드 기입: {기입한 필드 표시명 또는 유지}
- 상태 전환: 완료 ({착수 후 상태})
- 첨부 다운로드: {n}건 → {경로}
```

### 보류

```markdown
## 실행 결과 — {티켓 키}

- 상태 전환: 보류 ({사유: 번호 밖 / 사용자 취소 / transition unavailable / 티켓 없음})
```

### 첨부 토큰 없음 (Jira)

고정 문구. 완료 블록의 첨부 줄을 이것으로 바꾼다.

```markdown
- 첨부 다운로드: 보류 (토큰 파일 없음)
  한 번만: https://id.atlassian.com/manage-profile/security/api-tokens 에서 토큰 발급 후
  `{paths.jira_token_file}` 에 1행 이메일, 2행 토큰. 채팅에 붙여넣지 않음.
```

## §대상미확정

출력 후 심층 분석·§착수분석·계획 본문을 쓰지 않는다.

```markdown
## 대상 미확정 — {티켓 키 또는 요청 제목}

티켓 내용으로 수정할 화면·파일을 하나로 정할 수 없습니다. 분석은 하지 않습니다.

| # | 후보 파일 | 근거 |
|---|----------|------|
| 1 | … | … |

→ 분석할 파일명 또는 번호를 입력해 주세요.
```

---

## §착수분석 (계획 단계, 패치 없음)

대상 확정 후에만. 형식은 [plan-format.md](plan-format.md) 「착수분석」 표와 「구현 상세」.

- 구현 계획 행은 분석에서 잡은 호출 경로·쿼리만. 위치·변경이 빈 행은 넣지 않는다
- 「손대지 않음」은 안 고칠 파일, 「파급」은 안 고쳐도 영향받는 대상
- 소스 패치·쿼리 전문은 넣지 않는다
