# mapper

SQL 매퍼 XML(iBatis 2·MyBatis 3 등)을 쓰는 프로젝트의 기능. 매퍼 작성 규칙과 SQL 검증을 만든다.

## 사용자 안내

설명: 에이전트가 SQL 매퍼 XML을 고칠 때 같은 모듈의 기존 매퍼를 먼저 읽고 같은 구조로 쓰게 합니다. 바꾼 SQL은 완료 전에 개발 DB에서 실제로 조회해 보고, 필요하면 검사용 데이터를 넣어 확인합니다(지우지는 않음). 화면 요청에서 SQL까지 따라 읽는 서브에이전트도 함께 설치됩니다.

물어볼 것

1. `[처음 쓸 때]` (회사·조직별로 데이터를 나누는 키가 코드에 있을 때만) 검사에 쓸 개발 DB의 스키마와 회사 ID(`[test] dev_schema`·`dev_corp`)
   - 설치 때: 묻지 않고 비워 둔다. 처음 SQL 검사(C_SQL)를 할 때 에이전트가 묻고 적는다

묻지 않고 정하는 것

- 매퍼 위치·이름 규칙·세션 파라미터 표·프로젝트 고유 함정: 코드에서 찾은 내용 그대로 매퍼 폴더 `AGENTS.md`에 적는다
- 매퍼 반영 방식: 자동 재로딩 빈이 설정에 보이면 자동 반영. 매퍼 설정 파일이 VCS에서 빠져 찾지 못하면 서버 재기동이 필요하다고 보고 수정 후 안내에 재기동을 넣는다
- 검사용 데이터 키 앞에 붙일 짧은 이름(`[person] alias`): `[person] author`가 영문이면 소문자로 바꾼 값, 아니면 VCS 사용자 이름·이메일에서 뽑은 영문 이니셜

## 감지 신호

- `*Mapper.xml`, `*_SQL.xml`, `sqlMap*.xml`, `mybatis-config.xml`
- 의존성: `mybatis-*.jar`, `ibatis-*.jar`, `org.mybatis` (pom·gradle·`WEB-INF/lib`)
- DTD 선언: `sql-map-2.dtd`(iBatis 2) / `mybatis-3-mapper.dtd`(MyBatis 3)

## 원칙 (버전과 무관)

- SQL을 처음부터 새로 쓰지 않는다. 같은 모듈의 기존 매퍼를 먼저 읽고 구조(DOCTYPE, id 명명, 파라미터 문법, 동적 태그)를 따른다
- 문자열 치환 파라미터(iBatis `$p$`, MyBatis `${p}`)는 식별자(스키마·테이블)에만 쓴다. 값은 바인딩 파라미터로
- 없는 치환 파라미터가 에러 없이 빈 문자열이 되는 매퍼가 있다. 세션·공통 파라미터 이름은 프로젝트 표에 있는 것만 쓴다
- 테이블·컬럼은 DB 스키마 기준 문서로 확인한 뒤 쓴다. 추측 금지
- 큰 매퍼 XML은 전문을 Read하지 않는다. 검색으로 statement를 잡고 그 구간만 읽는다
- 조인을 추가할 때 같은 이름 컬럼 충돌(모호한 컬럼)을 피하려면 필요한 컬럼만 고른 서브쿼리로 조인한다

## 규칙 작성 항목 (set-up-harness가 프로젝트를 읽어 채움)

| 항목 | 읽을 곳 |
|---|---|
| 매퍼 종류·버전 | 의존성, DTD |
| 매퍼 파일 DTD | 매퍼 XML의 DOCTYPE. 매퍼 설정 파일(`sqlMapConfig`·`mybatis-config`)의 DTD와 다르므로 구분해 적는다 |
| 파일 위치·이름 규칙 | 매퍼 폴더 구조 |
| statement id 규칙 | 기존 매퍼 id와 DAO 호출 문자열 |
| 파라미터 문법·금지 문법 | 매퍼 종류 (아래 변형 표) |
| 동적 태그 | 기존 매퍼에서 쓰는 태그 |
| 세션·공통 파라미터 표 | 세션 객체 코드, 기존 매퍼의 반복 파라미터 |
| 프로젝트 고유 함정: 고정 스키마 테이블 | 기존 매퍼에서 테넌트(회사·스키마) 치환 파라미터 접두 없이 고정 스키마로 쓰는 테이블 목록. 규칙 문장도 함께 적는다: "이 테이블들에는 치환 파라미터 접두를 붙이지 않는다" |
| 프로젝트 고유 함정: 치환·바인딩 두 형태가 함께 있는 파라미터 | 같은 키를 치환(`$p$`/`${p}`)과 바인딩(`#p#`/`#{p}`) 두 가지로 쓰는 곳. 키마다 "새 코드의 기본형"을 적는다(예: 테넌트 ID처럼 값 비교에 쓰는 키는 새 코드에서 바인딩형, 스키마·테이블 이름처럼 식별자 자리는 치환형) |
| 프로젝트 고유 함정: 조인 시 같은 이름 컬럼 | 별칭 없는 컬럼이 남은 쿼리. 로그·이슈·주석에서 모호한 컬럼 오류의 DB 오류 코드·메시지를 찾으면 그대로 적는다(예: `ORA-00918 column ambiguously defined` 형식). 못 찾으면 코드·메시지 줄은 생략 |
| DB 방언 (페이징·NVL·별칭) | DB 종류, 기존 SQL |
| 수정 금지 설정 파일 | Spring·매퍼 설정 파일 |
| 매퍼 등록·재로딩 방식 | Spring 설정의 `mappingLocations`·sqlMap 설정(`configLocation`), 재로딩 빈. 설정 파일이 VCS 제외라 없으면 묻지 않고 재기동 필요로 본다. 자동 반영이면 재기동 안내를 넣지 않는다 |
| verify fixture 표 (「verify fixture」 절. verify C_SQL이 이 절 이름으로 찾음) | 주요 테이블의 NOT NULL·PK, 화면 조회 필수 컬럼 |

변형

| 매퍼 | 바인딩 | 치환 | 동적 태그 |
|---|---|---|---|
| iBatis 2 | `#p#` | `$p$` | `isNotEmpty`, `isEqual`, `iterate` |
| MyBatis 3 | `#{p}` | `${p}` | `if`, `choose`, `foreach`, `where`, `set` |

결과 → 매퍼 폴더의 `AGENTS.md`
