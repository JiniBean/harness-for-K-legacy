# 루트 AGENTS.md 구성

set-up-harness가 프로젝트 루트 `AGENTS.md`를 쓸 때 따르는 절 구성. 절 제목 아래 괄호는 채우는 방법이고, 결과 파일에는 남기지 않는다. 해당 없는 절은 빼고 번호를 다시 매긴다.

```markdown
# <프로젝트 이름> — 프로젝트 에이전트 지시 (정본)

이 파일과 소스 폴더의 `AGENTS.md`가 프로젝트 지시의 정본이다. 전역 공통 지시는 `~/.agents/AGENTS.md`에 있다. 여기에 다시 쓰지 않는다.

## 1. 지도
(text 코드 블록. 한 줄에 폴더 · 역할 · 폴더 AGENTS.md 위치. 빌드 산출물처럼 고치면 안 되는 폴더는 "수정하지 않는다")
(폴더 AGENTS.md 자동 로드에 기대지 않는다는 문단: 그 폴더 파일을 다루기 전에 내용이 컨텍스트에 없으면 직접 Read)

## 2. 스택 (고정)
(1단계에서 확정한 언어·프레임워크·매퍼·DB·UI·서버·빌드 도구와 버전. 버전 때문에 금지되는 것은 한 줄씩)
(형상관리: 도구, 브랜치 흐름, 에이전트 권한(커밋·푸시), 커밋 메시지 형식 위치)
(전체 요청 흐름 한 줄: 화면 → 컨트롤러 → … → 매퍼)

## 3. 업무 코드 (있을 때만)
(프로젝트 전체에서 쓰는 코드 체계. 값이 길면 docs로)

## 4. 항상 적용
(어떤 작업이든 파일을 열기 전부터 필요한 규칙만. DB 스키마 확인 절차, 기존 코드 먼저 읽기, 켠 기능의 핵심 금지 1~2줄, 큰 파일 전문 Read 금지, 테스트 정책(1단계 7번 결과))

## 4.1 변경 영향 (검토 서브에이전트가 읽음)
(프로젝트에서 읽은 것만. 없으면 절을 빼지 말고 `미확인`)
(공통 파일: 많은 화면·클래스가 함께 쓰는 파일과 고칠 때 영향 범위)
(짝 수정: 하나를 고치면 같이 고쳐야 하는 파일 쌍. 예 형식: 화면 ↔ 매퍼, 조회 쿼리 ↔ 엑셀 쿼리)
(대응 화면: 같은 기능의 다른 버전 화면)
(혼동 쉬운 키: 이름이 비슷하지만 뜻이 다른 파라미터·컬럼)

## 5. 조건부 문서 (해당 작업일 때 Read)
| 작업 | 문서 |
|------|------|
(.agents/docs/ 문서마다 한 줄. 4단계에서 만든 문서 포함)

## 6. 하네스 구성
(스킬·에이전트 이름 목록, 켠 기능 목록은 `.agents/harness.toml` `[harness] modules`(전역 기능은 `~/.agents/harness.toml`))
(훅·MCP 등록 파일은 직접 고치지 않는다. 절차는 `~/.agents/docs/harness-guide.md`)
(공용 도구 스크립트: 경로 · 용도 한 줄)
(일회성 파일 `.agents/tmp/`, 계획·리포트 `.agents/plans/`)
```

- 크기: 루트와 폴더 `AGENTS.md`를 이어 읽는 도구(Codex)는 합계 32 KiB에서 자른다. 긴 설명은 `.agents/docs/`로 빼고 표에 위치만 둔다
- 값은 `{섹션.키}`로 적는다. 비밀값은 적지 않는다
